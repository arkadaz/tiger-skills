ADR-001: Implement calculator as a pure-function Python module with no external dependencies

status: accepted date: 2026-06-18 deciders: benchmark@tiger.test, grill consulted: n/a informed: n/a

Context and Problem Statement

The benchmark project needs a reusable arithmetic module. The decision is how to structure src/calculator.py: as a class with methods, a module with pure functions, or a module using a third-party math library. Out of scope: CLI interface, floating-point precision extensions.

Decision Drivers

  • Zero external dependencies (portability for the benchmark harness).
  • Trivially testable — each operation is independently verifiable.
  • Minimal surface area — the benchmark must stay small and unambiguous.

Considered Options

  • Pure-function module (one function per operation, no class, no imports)
  • Class-based calculator with instance methods

Decision Outcome

Chosen option: "Pure-function module", because it has the smallest surface area, requires no instantiation ceremony, and each function is independently unit-testable without shared state.

ConsequencesStatement
GoodGood, because callers import one function at a time and each is independently mockable.
BadBad, because a class would allow future stateful extensions (e.g. history) more naturally — but that is explicitly out of scope.
ConfirmationE2E cases E1–E5 in e2e_testcases.robot verify each function imports and returns the correct value — python3 -m pytest src/ -q 2>&1 | grep -q 'passed'
Pros and Cons of the Options

Pure-function module

  • Good, because no class instantiation required at call site.
  • Good, because zero shared state means tests are fully isolated.
  • Neutral, because Python modules are singletons — effectively the same as a static class.
  • Bad, because adding stateful behaviour later requires a refactor.

Class-based calculator

  • Good, because easier to extend with state (history, precision settings).
  • Bad, because adds instantiation overhead for a stateless use case.

More Information

This decision is final for the benchmark scope. Any extension beyond the four basic operations would require a new feature and a superseding ADR.
