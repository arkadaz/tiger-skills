Spec: Four-operation calculator module with web UI

id: golden-001 grilled: 2026-06-18 stage: grill status: approved approved by: benchmark@tiger.test classification: missing-feature

Problem Statement

The codebase has no calculator module; arithmetic is inlined ad hoc across the project.

Objective & JTBD

Provide a reusable arithmetic module for the benchmark harness. When building numeric utilities, I want a reusable calculator module so I do not duplicate arithmetic logic.

User Context

  • Primary user: Developers on the Tiger benchmark project.
  • Environment: Python 3 project, no external dependencies.
  • Current workflow / pain: Arithmetic logic is duplicated inline; no single tested module exists.

Functional Requirements

IDRequirementNotes
FR1add(a, b) returns a + bPure function, no side effects.
FR2subtract(a, b) returns a - bPure function, no side effects.
FR3multiply(a, b) returns a * bPure function, no side effects.
FR4divide(a, b) returns a / b; raises ZeroDivisionError when b is 0Do not swallow the exception.
FR5A Flask web UI in src/app.py serves a numpad-style calculator at / on port 5000Digit buttons 0–9, operator buttons + - × ÷, a display showing the current expression, and an = button that shows the result. Page <title> must contain "Calculator". Divide-by-zero shows an error message in the display.

Happy Path

  1. Caller imports calculator from src/calculator.py → module loads without error.
  2. Caller invokes add(2, 3) → receives 5.
  3. Caller invokes divide(10, 2) → receives 5.0.
  4. User opens http://localhost:5000 → numpad calculator renders with digit buttons 0–9, operators, display, and =.
  5. User clicks 7 + 3 = → display shows 10.
  6. User clicks 1 ÷ 0 = → display shows an error message (not a crash).

Business Rules

RuleStatementRationaleVerification
BR1All four operations are pure functions with no external dependencies.Keeps the module portable and trivially testable.python3 -m pytest src/ -q 2>&1 | grep -q 'passed'
BR2Division by zero raises ZeroDivisionError (not swallowed).Caller must handle exceptional cases explicitly.python3 -m pytest src/ -q 2>&1 | grep -q 'passed'

Errors & Edge Cases

ScenarioExpected behavior
divide(1, 0)Raises ZeroDivisionError
add(-1, -1)Returns -2
multiply(0, 999)Returns 0

Constraints — CAN / CANNOT

  • CAN modify: src/calculator.py, src/app.py, src/templates/
  • CANNOT modify: anything outside src/
  • Must not break: no existing tests (none yet)

Metric

  • Why the user will notice: All arithmetic operations have a single, tested, importable home with a usable web interface.

Out of Scope

  • Floating-point precision beyond Python defaults.
  • Complex numbers, modular arithmetic, or any operation beyond the four basic ones.
  • REPL or CLI wrapper.
